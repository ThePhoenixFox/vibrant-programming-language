What is a Specification

Vibrant makes use of a language specification to define the syntax and semantics of the language. Specifications are important for implementation independence, allowing users to have a script that can run on any compliant Vibrant compiler. Although Vibrant only has one implementation the currently follows the specification closely, which would be the offical Vibrant compiler found here.

Keywords

The specification defines keywords that when used in the correct context produce valid Vibrant code. Keywords are reserved words that can not be used as identifiers for variables, functions, types, or constants. Keywords are case-sensitive and must be used exactly as defined in the specification. Keywords are the first thing a specification release defines.

Types

Vibrant provides a variety of built-in types as defined by the specification. Vibrant provides a variety of user-defined types that user can define like structs and enums. All derived and user-defined types rely on the primitive types at the first class level, however can rely on any type beyond this first class level. Some types are opaque, meaning their internal organization or size is unknown. Opaque types are exclusively used in references and pointers.

Statements

Vibrant programs are a list of statements, this is due to its imperative nature. Vibrant does not support expression control flow, only statement control flow is supported. Vibrant however does support a few functional features due to the lack of expression only computation.

Expressions

Vibrant programs statements are made from expressions. Expression are often the most complex part of a languages grammer. Vibrant expressions are composed of identifiers, operators, grouping, calls, and precedent.

What is the Vibrant Programming Language

Vibrant is a programming language that was designed from the ground up until code generation. It uses many external tutorials for inspiration and guidance. You can see the full list of the resources in the README.md.

Goals

The main goal of Vibrant is to be able to implement all of the features listed below. The benefits of this goal is learning more about how programming languages work under the hood. The project is designed to be able to learn how to implement a scanner, parser, semantic analyzer, and code generator (through LLVM). The secondary goal of Vibrant is to be able to create a programming language that is desired by own personal preferences. The has the benefits of being able to understand what feature are useful and how the standard library should be designed.

Features

1/3
TYPING

Vibrant is a STRONGLY and STATICALLY typed programming language. Vibrant provides many built-in types, and also allows users to define their own custom types. Vibrant has many built-in utility functions to convert between types. Vibrant is safe by default with its references and is fast when required with pointer types to manage variables in memory. Vibrant is immutable by default, reducing programming errors. Vibrant supports first class functions and type inferences.

2/3
PARADIGM

Vibrant is a imperative programming language at heart, with its statements and control flow. Vibrant however supports functional programming with first class functions. Vibrant currently does not support closures. Vibrant also supports object-oriented programming with its custom types. Vibrant currently does not specify standards for construction, destruction, or inhertance. Vibrant supports procedural programming with its functions and modularity.

3/3
MODULES

Vibrant provides a built-in modules system for code organization and the standard library. Vibrant modules can be imported from local files. Vibrant modules can export functions, types, constants, and variables. Vibrant also support preprocessor statements for including/excluding code. Vibrant preprocessor statements are scoped and do not leak into module outside of command-line arguments.
